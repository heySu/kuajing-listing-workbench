# 上架图合规工作台 · Listing Image Workbench

把**实拍基准图 → 白底净化 → 去 AI 水印 → 双单位尺寸线 → 合规自检 → 溯源报告**合成一条本地流水线。

纯前端单文件实现，零依赖、零网络请求，**图片不上传服务器**。打开 `listing-image-workbench.html` 双击即用，无需安装任何东西。

> 行业里 90% 的卖家在用 AI，但几乎全用在「生成内容」。这个工具只管生成之后不该交给模型的部分：**校验、留痕、别踩合规红线**。

## ✨ 功能

### ① 图像处理
- **平场校正压白**：按每行左右背景块拟合水平梯度，`img / gradient × 255`，专治整幅底色带渐变的实拍图，袋子褶皱与投影完整保留
- **柔和白场**：`lo/hi` 双阈值把近白背景推到 255，暗部主体不动；洗透明塑料时不会一片白
- **羽化去水印**：在预览图上拖框选中（或一键选右下角），逐列上下边界线性插值 + 羽化过渡；**框内完全替换**，避免边缘留一圈水印残字
- **双单位尺寸线**：cm/in 自动换算，导出时以工程线 + 白描边文字叠加，**不烧进底图**，改数字不用重新出图
- **统一输出**：1200 × 1200 白底方图；单张 PNG 或 store 模式 ZIP 批量导出
- **几何一致性对比**：载入实拍基准图，与成品图算归一化灰度相似度，提示格数/部件数量是否被 AI 改掉

### ② 合规自检
尺寸、1:1 比例、四角白度、右下角水印疑似、主体留白边距、主体占比共 6 项像素级检测 + 六层人工审查（意图 / 品牌 / 版权 / 文化 / 平台 / 授权）。

水印检测用**同高度左侧区域做暗像素对照**：带水平渐变的实拍底图右侧天然更亮，简单做四角纯度互比会把水印「抵消」掉造成漏检。

### ③ 溯源报告
导出 YAML，记录每张图的原始文件、主体包围盒、逐步处理参数、检测结论与人工审查结果。平台质疑图片来源、或复盘哪一步改坏了图时，这份记录就是证据链。

### ④ 方法 SOP
从实操里沉淀的六步流程与高频踩坑清单：几何锚点、以实拍图为 image1 只换内容、构图给水印留白、尺寸线不烧进 AI 图、细高产品先缩到 0.80 再标注、透明产品不能抠图合成场景等。

## 🧪 测试

```bash
node test-image-workbench.js
```

自测用 `vm` 直接加载交付 HTML 里 `<script id="core">` 的真实代码，不测副本。**15 项全过**，覆盖白场、平场校正、包围盒、羽化去水印、四角纯度、水印对照检测、合规判定、几何相似度、CRC32 与 ZIP 结构，另做两段脚本语法检查与 UI 层 DOM id 存在性/唯一性检查。

其中两项是开发时由自测抓出的真实缺陷：羽化蒙版在框内衰减会残留暗像素（包围盒误把水印算成主体），以及渐变底图上四角互比会漏检水印。

## ⚠️ 能力边界

- **不生成图片** —— 生成交给你惯用的模型，本工具接管生成之后不可控、不该交给模型的部分
- **不保证去水印成功** —— 只对平滑背景有效；水印压在产品硬边上应重新出图，别硬修
- **不写 EXIF / C2PA** —— 浏览器导出的 PNG 不携带元数据，YAML 是外部证据链。工具内附 `exiftool` / `c2patool` 补签命令模板
- **不构成合规保证** —— 自动检测只提示风险，右下角水印与几何结构必须人工放大核验；各平台主图规范与 AI 标识要求以官方当期政策为准
- **不联网、不存储** —— 关掉页面数据就没了，报告需要自行下载保存

## 🛠 技术实现

原生 HTML / CSS / JavaScript + Canvas，单文件约 1000 行，无框架、无构建、无外部资源。核心算法写成与 DOM 解耦的纯函数（`<script id="core">`），因此可以在 Node 里直接跑真实代码做回归测试。ZIP 为自实现的 store 模式打包（含 CRC32），支持中文文件名。

## 📌 定位

作者同时在一线做跨境上架图，工具里的规则与踩坑均来自实操，不是从平台文档抄来的清单——**给自己做的工具，顺便解决同类卖家的同一个问题**。
